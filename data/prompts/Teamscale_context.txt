Context: We study line-level defect prediction on real-world Java software projects. Each instance corresponds to a single source-code line. A line is labeled as buggy if it is marked as defective by the dataset's ground truth (e.g., via links to bug-fixing commits). For each line, we derive features from Teamscale's built-in (default) Java static-analysis checks. Each feature is encoded as a string identifier of the form type_name::severity (e.g., SomeCheckType::RED), and its value indicates whether that check triggers on the line under the configured severity (1 = triggered, 0 = not triggered). In Teamscale, check severity is expressed using two levels, RED and YELLOW: RED denotes critical, whereas YELLOW denotes non-critical (the severity is configurable in the analysis profile). We treat severity as part of the feature identity to capture this configuration explicitly.
